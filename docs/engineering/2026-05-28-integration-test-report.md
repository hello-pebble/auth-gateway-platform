# 📅 2026-05-28 개발 일지: [integration] 패널티 적용 시 엣지 케이스 및 동시 매칭 시나리오 통합 테스트(E2E)

## 1. 시작 전
- **목표**: 관리자의 패널티 부여와 사용자의 매칭 시도가 동시에 일어날 때의 시스템 안정성 및 정합성 검증
- **배경**: 개별 기능(패널티, 락)은 구현되었으나, 이들이 결합되었을 때 발생할 수 있는 복합적인 레이스 컨디션 방어 확인

## 2. 진행 과정

### 🚨 Case Study: 통합 시나리오 테스트 케이스
기능 간 상호작용 시 발생할 수 있는 복합 시나리오를 정의합니다.

*   **Case 6.1: 매칭 직전 패널티 부여 (Race between Penalty and Match)**
    *   **상황**: User A가 B를 선택하여 매칭이 성사되기 직전, 관리자가 User B를 영구 정지시킴.
    *   **검증**: 락(Lock) 덕분에 패널티 처리가 먼저 끝났다면 매칭은 실패해야 하며, 매칭이 먼저 끝났다면 이미 성사된 매칭이라도 패널티에 의해 접근이 차단되어야 함.
*   **Case 6.2: 일시 정지 만료 후 즉시 매칭 시도 (Expiration Edge Case)**
    *   **상황**: User B의 1일 정지가 23시 59분 59초에 끝남. User A가 00시 00분 01초에 B를 선택함.
    *   **검증**: Lazy Evaluation 로직이 정상 동작하여 별도의 배치 작업 없이도 즉시 매칭이 성사되는지 확인.
*   **Case 6.3: 정지된 유저들 간의 대량 추천 제외 확인**
    *   **상황**: 다수의 유저가 패널티를 받은 상태에서 추천 API 호출.
    *   **검증**: `getAllExposedUsers` 필터링에서 `isCurrentlyBlocked`가 정확히 작동하여 클린한 유저만 추천되는지 성능 부하와 함께 확인.
