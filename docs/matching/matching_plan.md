# 릴레이 소개팅 온라인 서비스 기획안

## 1. 서비스 개요
릴레이 소개팅은 기존의 1:1 매칭 방식에서 벗어나, 한 사용자가 여러 명의 후보자를 순차적으로 만나며 최종 호감도 점수에 따라 선택에 도달하거나, 지인이 다음 대상을 추천하는 방식의 소셜 네트워킹 서비스입니다.

## 2. 핵심 비즈니스 로직 (Problem - Solution - Result)

### 상황 및 문제 정의 (Problem)
* **선택의 피로도:** 무제한 매칭 방식은 사용자에게 과도한 선택지를 주어 오히려 결정을 어렵게 만듬.
* **신뢰성 부족:** 익명 기반의 매칭은 상대방의 신원이나 성향을 파악하는 데 비용이 많이 발생함.
* **낮은 몰입도:** 단순 스와이프 방식은 대화의 연결성이 떨어지고 일회성 만남에 그침.

### 기술적 솔루션 및 기능 (Solution)
* **큐 기반 릴레이 매칭:** 사용자가 대기열(Queue)에 진입하면, 시스템이 설정된 시간 간격에 따라 다음 후보자를 순차적으로 연결.
* **지인 기반 추천 체인:** 매칭이 종료된 후, 사용자가 상대방에게 어울릴 만한 지인을 추천하거나 피드백을 남겨 신뢰도를 높이는 시스템 구축.
* **실시간 트래픽 관리:** 특정 시간대에 몰리는 사용자 접속을 제어하기 위해 대기열 시스템을 도입하여 서버 부하 방지 및 사용자 이탈 최소화.

### 기대 효과 및 결과 (Result)
* **집중도 향상:** 정해진 시간 동안 한 사람에게만 집중하게 하여 매칭 성공률 제어 가능.
* **데이터 선순환:** 유저 피드백 데이터를 기반으로 한 정교한 추천 알고리즘 고도화.
* **플랫폼 안정성:** 대기열 로직을 통한 고가용성 아키텍처 확보.

## 3. 기술 스택 제안 (Backend Architecture)
> **현재 구현 상태:** 매칭 프로필·순위·성사 데이터와 대기열은 `ConcurrentHashMap` 기반 인메모리 저장소를 사용합니다. 아래 PostgreSQL·Redis·Kubernetes 구성은 구현 완료 항목이 아니라 향후 확장을 위한 설계 제안입니다.

* **Language & Framework:** Kotlin / Spring Boot
* **Database:** * PostgreSQL: 사용자 기본 정보 및 관계형 데이터 저장.
    * Redis: 실시간 대기열(Queue) 관리 및 세션 캐싱.
* **Infrastructure:** Docker, Kubernetes를 활용한 마이크로서비스 아키텍처(MSA) 및 GitLab CI/CD 파이프라인 구축.
* **Monitoring:** Log-based monitoring (ELK Stack 등)을 통한 트래픽 surge 및 오류 추적.

## 4. 서비스 워크플로우
1.  **참가 신청:** 사용자가 선호하는 테마나 시간대에 릴레이 소개팅 신청.
2.  **대기열 진입:** 시스템이 적절한 매칭 그룹을 생성하고 유저를 큐에 배치.
3.  **릴레이 진행:** 1세션(예: 10분) 동안 대화 후, 다음 순번의 유저와 자동으로 연결.
4.  **최종 선택:** 모든 릴레이가 종료된 후, 호감을 느낀 유저를 최종 선택.
