# 프로젝트에서 실제로 한 것
---

### 1단계 — 설계 문서 먼저 작성 (내가 주도)

구현 전에 항상 문제 정의와 선택 근거를 먼저 적었다.

**내가 작성한 것:**
- `docs/PROJECT_MANIFESTO.md` — "왜 이걸 만드는가"
- `docs/DECISION_LOG_WHY.md` — 각 설계 결정에서 A/B/C 중 A를 선택한 이유
- 각 Phase 아키텍처 문서 (`docs/architecture/phase*.md`)

**Claude Code의 역할:**  
설계 문서 초안이 논리적으로 빠진 부분이 없는지 검토.

---

### 2단계 — TDD: 실패 테스트 먼저, 구현 나중 (AI와 페어)

테스트를 먼저 작성하고 AI가 통과 코드를 작성하는 사이클을 유지했다.

**실제 예시 — aud 클레임 검증 추가:**

```
내가 한 것:
1. "JWT에 aud 클레임이 없으면 리소스 서버별 검증이 불가능하다"는 문제 인지
2. 테스트 시나리오 설계: "access token에 aud가 포함되어야 한다"
3. 테스트 파일 작성 지시: JwtProviderAudTest.kt

Claude Code가 한 것:
- 테스트 코드 초안 작성 (reflection으로 RSAPrivateKey 주입, JWT 파싱 검증)
- JwtProvider.kt에 .audience().add(listOf("task-service", "matching-service")).and() 추가

내가 한 것:
- 생성된 코드가 실제 프로젝트 패턴과 맞는지 검토
- 테스트 실행 결과 확인 및 최종 승인
```

---

### 3단계 — 버그 발생 시: 현상 설명 → AI 분석 → 내가 판단

버그를 발견하면 현상을 구체적으로 설명하고, 원인 분석을 AI와 함께 했다.

**실제 예시 — BUG-001 (isBlocked 리셋 버그):**

```
내가 발견한 것:
관리자가 userId=1을 차단했는데, 사용자가 노출 설정을 변경하면 차단이 풀림

내가 설명한 것:
updateExposure()가 기존 프로필을 읽지 않고 새 객체를 생성 중
→ isBlocked 기본값 false로 초기화되는 현상

Claude Code가 한 것:
- read-modify-write 패턴으로 수정 코드 제안
- 회귀 테스트 코드 작성

내가 한 것:
- 수정 방향이 맞는지 판단 (copy() 패턴 선택)
- BUG-001 문서로 기록 (docs/engineering/bug-reports/)
```

---

### 4단계 — 아키텍처 결정: AI는 옵션 제시, 나는 선택

중요한 설계 결정은 항상 내가 했다. AI는 각 옵션의 trade-off를 정리하는 데 활용했다.

**실제 예시 — 관리자 API 격리 방식:**

```
내가 고민한 것:
관리자 API를 어디에 두어야 Gateway 설정 실수로 노출되지 않을까?

AI와 함께 정리한 옵션:
A. admin-module 분리 + /internal/admin/** Gateway 미노출
B. matching-module 내 /admin 경로
C. Gateway 필터에서 ROLE_ADMIN 검증

내가 선택한 것: A
이유: 권한 검증 단일화 + 내부 API 물리적 격리
(설명은 docs/DECISION_LOG_WHY.md에 기록)
```

---

### 5단계 — 문서화: 구현 완료 후 문서로 정리

시나리오로 완료된 기능은 이력서 소재가 될 수 있도록 문서로 정리했다.

**실제 예시 — docs/scenarios.md:**
- 어떤 문제가 있었는지
- 어떻게 해결했는지
- 결과가 어떻게 달라졌는지
- 이력서 한 줄로 압축

이 문서 자체도 Claude Code와 함께 작성했지만, 각 시나리오의 내용(문제 인지, 해결 방향)은 내가 직접 경험한 것을 기반으로 했다.

---

## 내가 직접 한 것 vs AI가 도운 것

| 항목 | 내가 한 것 | AI가 도운 것 |
|---|---|---|
| 문제 정의 | ✅ 직접 | — |
| A/B/C 설계 비교 | ✅ 직접 | 옵션 정리 |
| 설계 문서 작성 | ✅ 직접 | 검토·보완 |
| 테스트 시나리오 설계 | ✅ 직접 | 코드 초안 |
| 테스트 코드 작성 | 방향 설계 | ✅ 초안 작성 |
| 구현 코드 작성 | 검토·수정 | ✅ 초안 작성 |
| 버그 인지·분석 | ✅ 직접 | 원인 분석 보조 |
| 수정 방향 결정 | ✅ 직접 | 옵션 제시 |
| 시나리오 문서화 | ✅ 직접 | 구조화 보조 |
