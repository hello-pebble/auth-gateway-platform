# 📝 개발 일지 작성 가이드 (Git Wiki)

이 문서는 프로젝트의 개발 기록을 간단명료하게 남기기 위한 템플릿 가이드입니다.

## 📁 파일 명명 규칙
- `yyyy-mm-dd-작업명.md` (예: `2026-05-20-auth-migration.md`)
- 모든 파일명은 **소문자**로 작성합니다.

---

## 템플릿 (옵션 2: 리스트 형식)

### 📅 YYYY-MM-DD 개발 일지: [작업 제목]

**1. 시작 전**
- **목표**: (예: 가상 대기열 API 성능 최적화)
- **배경**: (예: Phase 4 트래픽 제어 전략의 일환)

**2. 진행 과정**
- [ ] 구체적 수행 내용 1
- [ ] 구체적 수행 내용 2
- [ ] 발생한 이슈 및 해결 방법 (간략히)

**3. 마무리**
- **결과**: (예: 응답 속도 20% 개선, 테스트 통과)
- **다음 단계**: (예: 프론트엔드 연동)
- **관련 문서**: (예: `docs/DECISION_LOG_WHY.md`)

---

## 작성 원칙
1. **간단명료**: 불필요한 수식어 없이 기술적 사실 위주로 작성합니다.
2. **Phase 연계**: 현재 진행 중인 Phase(예: Phase 4)와의 연관성을 명시합니다.
3. **이모지 활용**: 
   - 시작 전: `🚀`
   - 진행 과정: `🛠️`
   - 마무리: `🏁`
